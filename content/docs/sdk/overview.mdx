# SDKs

Each SDK wraps the Shop API: it adds the credential headers, builds the locale-prefixed
URL, unwraps the response envelope, and retries `429` and `5xx` for you.

## What they cover

| | JavaScript | PHP | Python |
|---|---|---|---|
| Transactions and points | Yes | Yes | Yes |
| Loyalty card lookup | Yes | Yes | Yes |
| Coupons | Yes | Yes | Yes |
| Games and stamp cards | Yes | Yes | Yes |
| Offers (read) | Yes | Yes | Yes |
| XML product import | Yes | Yes | Yes |
| QR login and QR card scan | Yes | Yes | Yes |
| Realtime subscription helpers | Yes | – | – |
| React components | Yes | – | – |

QR results arrive over a realtime channel in every language — that is the path to
build. The JavaScript SDK opens the subscription for you; in PHP and Python the
subscription belongs in the browser, and the SDK gives you the connection details
(`getRealtimeConfig`). Polling exists as a fallback for environments that cannot hold
a WebSocket open.

## Configuration

Every SDK takes the same four things:

```
apiKey       your API key,  lty_...
apiSecret    your API secret
environment  'production' (default) or 'staging'
locale       'lt' (default) or 'en'
```

Credentials come from the [Partners Portal](https://partners.loyalty.lt) →
**API Credentials**. Keep the secret server-side — these SDKs are for backends and
POS software, not for browser or mobile bundles.

## The call most integrations start with

<CodeGroup>
```typescript JavaScript
await sdk.createTransaction({
  user_email: 'customer@example.com',
  order_id: 'ORD-2024-001',
  order_total: 25.50,
  currency: 'EUR',
  shop_id: 1,
});
```

```php PHP
$sdk->createTransaction([
    'user_email'  => 'customer@example.com',
    'order_id'    => 'ORD-2024-001',
    'order_total' => 25.50,
    'currency'    => 'EUR',
    'shop_id'     => 1,
]);
```

```python Python
sdk.create_transaction(
    user_email='customer@example.com',
    order_id='ORD-2024-001',
    order_total=25.50,
    currency='EUR',
    shop_id=1,
)
```
</CodeGroup>

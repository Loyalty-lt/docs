# QR Features

Two QR flows, both driven from your server:

- **QR login** — the customer scans to sign in, and you get their JWT.
- **QR card scan** — the customer scans at the till, and you get their loyalty card.

Sessions expire after 5 minutes.

**Your server opens the session; the browser waits on the realtime channel.** That is
the path to build — the result lands the instant the customer confirms, with no
request per second and no lag at the till. The PHP SDK has no subscription helper
because the subscription belongs in the page, not on the server.

## Receiving the result

The result arrives on a realtime channel, not in a response body. The SDK subscribes
for you and blocks until the session resolves:

```php
$session = $sdk->generateQrLogin('Till 3', $shopId);
// render $session['qr_code'], then wait on the channel
$result = $sdk->subscribeQrLogin($session['session_id']);

if (($result['status'] ?? null) === 'authenticated') {
    $token = $result['token'];
    $user  = $result['user'];
}
```

Pass a callback to watch every frame instead of only the final one. The helper returns
`None`/`null` if nothing resolved within the timeout — sessions last 5 minutes.

<Note>
The realtime helpers need a WebSocket client: `composer require phrity/websocket`. Without it the SDK still works;
only these two methods raise.
</Note>

Because it blocks, use it from a POS, a CLI or a worker. In a web request, open the
session on your server and let the page subscribe — channels, events and payloads are
in [Realtime](/docs/api-reference/realtime).

## QR login

Open the session on your server, render the QR code, and let the page wait on the
channel above.

```php
$session = $sdk->generateQrLogin('Till 3', $shopId);
// render $session['qr_code'] as a QR image; the page subscribes to
// qr-login.{$session['session_id']} and receives the token there
```

### Fallback: polling

Only if the page cannot hold a WebSocket open. Never block a PHP worker in a loop —
expose the poll as your own endpoint and call it from the browser:

```php
// routes/web.php
Route::get('/loyalty/qr-status/{sessionId}', fn (string $sessionId) =>
    response()->json($sdk->pollQrLogin($sessionId))
);
```

The status is `authenticated` when the customer confirms, and the response then
carries `token` and `user`.

| Status | Meaning |
|--------|---------|
| `pending` | Waiting for the customer to scan |
| `scanned` | Scanned; waiting for confirmation in the app |
| `confirmed` | Confirmed; the token is being issued |
| `authenticated` | Done — `token` and `user` are present |
| `cancelled` | The customer declined |
| `expired` | Generate a new session |

### If the customer has no app

```php
$sdk->sendAppLink('+37060000001', $shopId);
```

## QR card scan

The POS flow: identify the card without asking for a phone number.

```php
$session = $sdk->generateQrCardSession('Till 3', $shopId);
// render $session['qr_code']; the till subscribes to qr-card.{$session['session_id']}
// and receives card_data the moment the customer scans
```

`card_data` carries `loyalty_card_id`, `card_number`, `points` and `user`. If the till
cannot hold a WebSocket open, `$sdk->pollQrCardStatus($session['session_id'])` returns
the same thing, one request at a time.

## Finishing the sale

```php
$coupons = $sdk->getCardCoupons($shopId, $card['loyalty_card_id']);
$games   = $sdk->getCardGames($card['loyalty_card_id'], $shopId);

$sdk->createTransaction([
    'user_id'     => $card['user']['id'],
    'order_id'    => 'POS-' . time(),
    'order_total' => $total,
    'currency'    => 'EUR',
    'shop_id'     => $shopId,
]);

foreach ($games as $game) {
    $sdk->addStamps($game['id'], $card['loyalty_card_id'], $shopId, 1);
}
```

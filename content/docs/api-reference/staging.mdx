# Staging

Staging is a full copy of the API with demo data. Build and test against it, then
change one URL to go live.

| | Staging | Production |
|---|---------|------------|
| Base URL | `https://staging-api.loyalty.lt` | `https://api.loyalty.lt` |
| Data | Demo only | Real customers |
| Credentials | Staging pair only | Production pair only |
| Reset | Every Sunday 05:00 EET | Never |

Create a staging key/secret in the [Partners Portal](https://partners.loyalty.lt) →
**API Credentials** → environment **Staging**. Staging credentials are rejected by the
production API and vice versa.

## Weekly reset

Sundays at 05:00 EET, staging clears transactions, point awards, game progress and
coupon redemptions. Partner settings, the catalogue, demo cards, demo staff and your
API credentials survive.

## A first end-to-end test

```javascript
// 1. Credentials reach the API
await sdk.validateCredentials();

// 2. Look up a demo card
const card = await sdk.getLoyaltyCardInfo({ card_number: '900-001-001' });

// 3. Register a purchase — this awards the points
await sdk.createTransaction({
  user_email: 'demo1@loyalty.lt',
  order_id: `TEST-${Date.now()}`,
  order_total: 25.50,
  currency: 'EUR',
  shop_id: 1,
});

// 4. Read the new balance
const balance = await sdk.getPointsBalance({ card_number: '900-001-001' });
```

Then reverse it, using the same `order_id`:

```javascript
await sdk.createTransaction({
  user_email: 'demo1@loyalty.lt',
  order_id: 'TEST-...',      // the same order_id as above
  type: 'refund',
  order_total: 25.50,
});
```

## Common problems

<AccordionGroup>
  <Accordion title="401 Unauthorized">
    Staging credentials only work against `staging-api.loyalty.lt`. Check the base URL,
    that both headers are present, and that the credential is still active in the
    Partners Portal.
  </Accordion>

  <Accordion title="404 card not found">
    Use the demo card numbers above. Production cards do not exist in staging.
  </Accordion>

  <Accordion title="422 on transactions/create">
    `order_id` is required, and so is one of `user_id` or `user_email`. Read the
    `errors` object in the response — it names the field.
  </Accordion>
</AccordionGroup>

Stuck? [developers@loyalty.lt](mailto:developers@loyalty.lt) — include your partner ID
and the `request_id` from the response.
